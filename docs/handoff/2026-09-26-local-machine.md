# Техзадание: перенос работы на локальную машину и следующие шаги

Дата: 2026-09-26. Предыдущая работа шла в облачной сессии Claude Code на ветке
`claude/awesome-goodall-4tfsko`. Выпущена версия 0.2.2, синхронизация Mac ↔ Windows
проверена руками, автообновление работает.

## 1. Какую машину и модель брать

- **Основная машина — Mac.** Часть функций (ярлыки папок через bookmarks, Quick Look-миниатюры,
  буфер обмена NSPasteboard) есть только на macOS, CI-гейты тоже на macOS. Windows — для ручной
  проверки после релиза.
- **Приложение:** Claude Desktop → вкладка Code, или `claude` в терминале в папке проекта.
  Оба читают `CLAUDE.md` из корня автоматически.
- **Модели:**
  - Sonnet — основная разработка, фичи, багфиксы (по умолчанию).
  - Opus — архитектурные шаги: разбиение `App.tsx`, ADR для групп, PAKE в сопряжении, сжатие журнала.
  - Переключение: `/model` в сессии.

## 2. Разовая настройка Mac

1. Инструменты: Xcode Command Line Tools (`xcode-select --install`), Rust (`rustup`, stable),
   Node 22, GitHub CLI (`brew install gh`, затем `gh auth login`).
2. Код:
   ```
   git clone https://github.com/butcherbro/MySpace.git
   cd MySpace
   git checkout claude/awesome-goodall-4tfsko
   npm ci
   npx playwright install chromium
   ```
3. Проверка, что всё собирается: прогнать гейты из `CLAUDE.md`, затем `npm run tauri dev`.
4. Установленная из релиза версия и `tauri dev` используют одну базу. Во время отладки закрывай
   установленную, чтобы два процесса не писали одновременно.

## 3. Порядок работ (по важности)

1. **Влить ветку в `main`.** Создать PR `claude/awesome-goodall-4tfsko` → `main`, дождаться зелёного CI,
   смёржить. Дальше вся работа — в новых ветках от `main`. Проверить, что `release.yml` по тегу собирает с `main`.
2. **Разбить `App.tsx` (≈2 700 строк, цель < 800).** Модель: Opus. Вынести по фичам в хуки с собственными
   тестами: вставка и буфер обмена, контекстные меню, дроп файлов, синхронизация и опрос изменений,
   обложки досок, работа с картинками. Поведение не меняется; гейты и e2e зелёные после каждого шага.
   Один шаг — один коммит.
3. **Связи между карточками (connectors).** Описание в `tasks/todo.md`, раздел «Следующие фичи».
   Новая сущность, своя таблица, свой тип в журнале синхронизации, плавающая стрелка React Flow.
4. **Группы (подложка с названием).** Там же. Перед началом — ADR на полстраницы (Opus).
5. **Долг синхронизации перед раздачей другим людям** (`tasks/todo.md`, раздел «Sync»):
   - PAKE вместо HMAC-кода в сопряжении;
   - приватный ключ устройства вне базы (системное хранилище ключей);
   - сжатие журнала, когда все пары прочитали строки;
   - заглушка «ждём файл» для картинки, чей блоб ещё не пришёл;
   - повторное обнаружение пары при смене IP.
6. **Аудит P2** (`docs/audits/…`, раздел 5): постраничная загрузка корзины, списка досок и MCP-чтения;
   z-order (на передний/задний план); e2e против настоящего Rust; экспорт/импорт пространства архивом.

## 4. Как выпускать версии

- Локально теги пушатся без ограничений: поднять версию в трёх файлах, смёржить в `main`,
  `git tag vX.Y.Z && git push origin vX.Y.Z`.
- Без терминала: GitHub → Actions → Release → Run workflow (tag = версия, ref = ветка).
- Проверка: `gh run watch` или вкладка Actions. Пока все три сборки не зелёные, релиз — черновик.

## 5. Отладка

- Логи бэкенда: `~/Library/Application Support/com.bro.myspace/myspace.log`.
- DevTools в `tauri dev`: правый клик в текстовом поле → Inspect, или Cmd+Option+I.
- Синхронизация: диалог Корзина → Devices…; события `sync-state` и `sync-applied` видны в консоли DevTools.
- Проблемы на Windows: собрать там `npm run tauri dev`, прислать хвост `%APPDATA%\com.bro.myspace\myspace.log`.
