## Rules that must not be lost

- Run every command from the worktree, never from the main checkout: `main` still
  carries the old asset GC that deleted File Card assets.
- Do not cherry-pick into `main`. The stabilization arrives as one package so the
  data-integrity fixes stay independently reviewable and revertible.
- Never test destructive behaviour against the live library under
  `~/Library/Application Support/com.bro.myspace`; automated tests use temporary
  databases and asset directories.
- One commit per task; write commit messages to a file and use `git commit -F`
  (apostrophes and quotes otherwise break the shell).
- The React Compiler lint rules make declaration order load-bearing: referencing a
  value before it is declared is an error even inside an effect closure. When a
  controller needs something declared later, pass a ref and fill it in an effect.
- In hook tests the gateway must be a stable object (as `useMemo` makes it in the
  app); a fresh object per render restarts the mount effect and loops.
- Running the app from the worktree rebuilds and restarts it, and startup paths
  (migrations, favicon collapse, asset GC) then act on the live library. That is
  expected, and every run takes a snapshot first.
